# Architecture

The edit manifest is the source of truth for video. Parsing and validation convert it into immutable `Project`, `Shot`, and `Grade` values. `models` also computes playback durations, and the timeline module calculates transition overlap offsets; neither depends on FFmpeg. The filter-graph builder turns the project into filter syntax, while `FFmpegRenderer` handles input validation, command assembly, process execution, and atomic delivery. `probe` provides a read-only adapter for FFprobe; `credits` writes the soundtrack attribution alongside the render. `qa` verifies a finished render and builds its review contact sheet, `source_review` builds the paged source-audit sheets and CSV, and `looks` defines the named grade presets. `dehaze_clip` is the separate `tripdehaze` preprocessing command.

The image path is independent of the video manifest. `image_processing` accepts painted grayscale masks from an image editor or optional MaskFormer ADE20K masks. It applies different detail-sharpening strengths by region, gates sharpening by local texture, fades mask effects inward from boundaries, clips high-pass detail to limit ringing, and can lift selected highlights through a separate mask. A color-overlay preview makes selections visible. OpenCV, Pillow, and NumPy are optional image dependencies; ONNX Runtime is only needed for automatic masks. Photo adjustments preserve dimensions and do not synthesize scene content. The current `tripimage` scope is selective sharpening and masked lightness lift, not complete color grading, dehaze, look profiles, interactive masks, or batch review. See `image-workflow.md` for the separate still-photo workflow and its required holistic visual quality gate.

Video editing decisions (clip in-points, speed, grade, transitions, location slates, and portrait layout) remain separate from rendering mechanics. A future NLE or alternate encoder can consume the same project data without changing the project format. FFmpeg calls use argument arrays rather than shell command strings, and rendered files are promoted into place only after a successful encode.
